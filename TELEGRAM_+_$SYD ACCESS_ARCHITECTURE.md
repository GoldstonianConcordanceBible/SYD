# SYD CALL POLICY
## Formal Market Call Standard
A SYD Call becomes official only after it receives a formal Call ID.
Example:
`SYD-CALL-0001`
A market observation without a Call ID is commentary.
A formal Call ID creates an auditable record.
---
# CALL LIFECYCLE
THESIS
↓
CALL ID
↓
TIMESTAMP
↓
INSTRUMENT
↓
DIRECTION
↓
REFERENCE / ENTRY ZONE
↓
INVALIDATION
↓
RISK
↓
CATALYSTS
↓
UPDATES
↓
CLOSE / INVALIDATION
↓
RESULT
↓
AFTER-ACTION REVIEW
↓
GITHUB CASE RECORD
↓
POTENTIAL COURSE OBJECT
---
# REQUIRED CALL FIELDS
Every formal call should identify:
**CALL ID**
**TIMESTAMP**
**ASSET / MARKET**
**ACTUAL INSTRUMENT**
**DIRECTION**
**REFERENCE / ENTRY AREA**
**THESIS**
**INVALIDATION**
**RISK CLASSIFICATION**
**TIME HORIZON**
**KNOWN CATALYSTS**
**AFFILIATION / CONFLICT DISCLOSURE**
**STATUS**
---
# STATUS VALUES
A formal call may be:
`WATCH`
`ACTIVE`
`UPDATED`
`PARTIALLY CLOSED`
`CLOSED`
`INVALIDATED`
`CANCELLED BEFORE ENTRY`
`ARCHIVED`
---
# NO RETROACTIVE THESIS EDITING
The original thesis should not be silently rewritten after the outcome becomes known.
Corrections and updates should receive a new timestamp.
Example:
`SYD-CALL-0041`
Original.
Then:
`SYD-CALL-0041-A`
First update.
Then:
`SYD-CALL-0041-B`
Second update.
Then:
`SYD-CALL-0041-CLOSED`
Final record.
---
# LOSING CALLS
Losing calls remain part of the record.
Do not remove a call because:
- the thesis failed,
- the stop/invalidation occurred,
- the market reversed,
- the outcome became embarrassing.
A failed call is educational evidence.
---
# NO GUARANTEED LANGUAGE
Formal SYD Calls should not use language such as:
- guaranteed,
- can't lose,
- risk free,
- certain profit,
- guaranteed floor,
- guaranteed return.
Market outcomes are uncertain.
---
# POSITION SIZE
Unless a service has separately established an appropriate and compliant personalized framework, SYD Calls should not tell a specific individual exactly how much of their wealth to risk.
The core call record focuses on:
- market thesis,
- instrument,
- invalidation,
- scenario,
- risk.
---
# AFFILIATED ASSETS
If the call concerns:
- $SYD,
- $C,
- $GCB,
- another ecosystem token,
- a project owned by an instructor,
- an asset where a contributor has a material financial relationship,
the affiliation must be disclosed.
---
# CALL QUALITY STANDARD
A call without invalidation is incomplete.
A call without an identifiable instrument is incomplete.
A call published only after the outcome is known is not a live call.
---
# CORE PRINCIPLE
## RECORD THE THESIS BEFORE THE RESULT.

FILE 3 — telegram/CALL_ID_STANDARD.md

# SYD CALL ID STANDARD
## Format
`SYD-CALL-XXXX`
Examples:
`SYD-CALL-0001`
`SYD-CALL-0002`
`SYD-CALL-0010`
`SYD-CALL-0100`
---
# UPDATE FORMAT
Updates append a letter.
Example:
`SYD-CALL-0047-A`
`SYD-CALL-0047-B`
`SYD-CALL-0047-C`
---
# FINAL STATES
Examples:
`SYD-CALL-0047-CLOSED`
`SYD-CALL-0047-INVALIDATED`
`SYD-CALL-0047-CANCELLED`
---
# SEQUENTIAL NUMBERING
Call IDs should be sequential.
Do not:
- skip losing calls,
- renumber history,
- delete a number and reuse it,
- create a second call with an existing ID.
---
# PUBLIC SAMPLING
The initial public sampling rule is based on the Call ID sequence.
Every tenth formal call is designated:
`PUBLIC + FLOOR`
Examples:
`0010`
`0020`
`0030`
`0040`
All other calls:
`FLOOR`
unless another documented exception applies.
This makes the public sample predictable before the result is known.
---
# WHY THIS MATTERS
If the public feed only showed winners, the public sample would be biased.
Sequential sampling creates an auditable rule.
---
# REGISTRY
A future registry should contain:
CALL ID
CREATED AT
ASSET
INSTRUMENT
DIRECTION
PUBLIC / FLOOR CLASSIFICATION
STATUS
CLOSE DATE
GITHUB CASE URL
COURSE URL
---
# RULE
## THE ID IS NEVER REUSED.

# 10%

- provide educational value,
- document performance transparently,

# INITIAL SAMPLING METHOD
The default rule is:
## EVERY 10TH FORMAL SYD CALL IS PUBLIC.
Examples:
`SYD-CALL-0010`
`SYD-CALL-0020`
`SYD-CALL-0030`
`SYD-CALL-0040`
These calls appear in both:
**SYD | WIRE**
and
**SYD | THE FLOOR**
---
# WHY THE RULE IS PREDETERMINED
The public call should be selected before the result is known.
This prevents:
- cherry-picking winners,
- hiding public losses,
- changing the sample after the fact.
---
# PUBLIC CALL CONTENT
A public formal call should use substantially the same formal structure as a gated call:
- Call ID
- timestamp
- market
- instrument
- thesis
- invalidation
- risk
- status
---
# PUBLIC UPDATES
If a public call receives an update, the public feed should receive the corresponding material update.
A public call should not become artificially better because losing updates were withheld.
---
# PUBLIC INVALIDATION
If a public call fails:
Publish:
`INVALIDATED`
Do not simply stop mentioning the trade.
---
# PUBLIC CLOSE
After closure:
Publish:
- result,
- after-action review,
- educational lessons.
---
# EDUCATIONAL DELAYED CONTENT
Calls not included in the live public 10% may later become:
- delayed case studies,
- courses,
- YouTube videos,
- Substack articles,
- GitHub records.
The live-access distinction may expire after the market value of immediacy has passed.
---
# PUBLIC PROMISE
The public receives:
## A SAMPLE OF THE LIVE FEED.
The public does not receive:
## THE COMPLETE LIVE FEED.
---
# RULE
## DO NOT CHOOSE THE PUBLIC CALL AFTER YOU KNOW WHETHER IT WON.
